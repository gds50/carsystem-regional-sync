# PRD / MVP — Carsystem Regional Sync Plugin

## 1. Продукт

WordPress-плагин для регионального сайта-копии `carsystem.su`, развернутого через Duplicator.

Плагин устанавливается **только на региональный сайт**.

Источник данных:
- основной сайт `https://carsystem.su`
- синхронизация через WordPress REST API и WooCommerce REST API
- аутентификация через WordPress Application Passwords

## 2. Главная цель

После клонирования основного сайта на новый поддомен администратор должен:

1. настроить подключение к основному сайту;
2. задать словарь региональных замен;
3. указать данные партнёра;
4. задать исключения по slug;
5. вручную запустить первичную регионализацию;
6. затем получать ежедневные обновления с основного сайта.

## 3. Пользователь

Единственный рабочий пользователь плагина в MVP: `caradmin`.

## 4. Что входит в MVP

- settings page в админке;
- хранение конфигурации;
- тест соединения с API;
- словарь замен в текстовом виде;
- список исключений по slug;
- первичная регионализация товаров и категорий;
- ежедневная синхронизация:
  - товаров WooCommerce;
  - категорий WooCommerce;
  - обычных страниц WordPress;
- карта соответствия remote/local объектов;
- журнал операций;
- безопасный запуск вручную и по cron.

## 5. Что не входит в MVP

- плагин на основном сайте;
- sync записей;
- sync пользователей;
- sync комментариев;
- sync заказов;
- sync остатков;
- sync 1С;
- двусторонний обмен;
- smart text processing;
- автоматическое управление складом.

## 6. Сущности синхронизации

### 6.1 Товары
Синхронизируем:
- title
- slug
- status
- content
- excerpt
- categories
- SEO meta:
  - `seo_meta_title`
  - `seo_meta_description`

Не меняем словарём:
- название товара
- H1 товара
- полное описание
- краткое описание

### 6.2 Категории
Синхронизируем:
- name
- slug
- description
- SEO meta:
  - `seo_meta_title`
  - `seo_h1`
  - `seo_meta_description`

### 6.3 Страницы
Синхронизируем:
- title
- slug
- status
- content
- excerpt

Для страниц регионализация SEO не выполняется.

## 7. Исключения

По умолчанию в настройках должны быть:

- `gde-kupit`
- `dostavka`
- `privacy-policy`
- `polzovatelskoe-soglashenie`
- `oplata`

Требования:
- список редактируемый;
- можно добавлять новые slug;
- можно удалять стандартные значения;
- исключённые slug не участвуют ни в синхронизации, ни в регионализации.

## 8. Регионализация

Регионализация строго словарная.

Формат строки:

```text
что_заменить => на_что_заменить
```

Правила:
- пустые строки игнорировать;
- некорректные строки не должны ломать обработку;
- замены применять только к разрешённым SEO-полям товаров и категорий;
- сначала длинные фразы, потом короткие;
- никаких «умных» догадок и морфологии.

## 9. Новые объекты

Если на основном сайте появились:
- новый товар;
- новая категория;
- новая страница,

плагин создаёт локальный объект, связывает его с remote ID и сохраняет служебные данные.

## 10. Удалённые или скрытые объекты

В MVP физически не удаляем.

Если объект на основном сайте снят с публикации, удалён или больше не возвращается API:
- локально переводим в draft / unpublish.

## 11. Успех MVP

MVP считается успешным, если:

1. подключение к основному сайту проверяется из админки;
2. первичная регионализация работает для товаров и категорий;
3. ежедневная синхронизация обновляет товары, категории и страницы;
4. исключения соблюдаются;
5. словарь меняет только нужные SEO-поля;
6. все операции видны в логах;
7. доступ к плагину есть только у `caradmin`.

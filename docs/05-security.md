# Безопасность

## 1. Модель доступа

Плагин предназначен только для пользователя `caradmin`.

Проверка должна состоять из двух условий:
- capability check
- username check

Рекомендуемое правило:
- пользователь должен иметь `manage_options`
- и `wp_get_current_user()->user_login === 'caradmin'`

## 2. Админка

- меню плагина видно только `caradmin`;
- страницы плагина доступны только `caradmin`;
- ручной запуск синхронизации и регионализации — только `caradmin`.

## 3. Формы

Каждая форма должна использовать:
- `wp_nonce_field()`
- `check_admin_referer()`

Каждое save/run действие:
- проверяет права;
- проверяет nonce;
- санитизирует входные данные;
- безопасно обрабатывает ошибки.

## 4. Входные данные

Требования:
- URL: `esc_url_raw()`
- login: `sanitize_user()`
- email: `sanitize_email()`
- текстовые поля: `sanitize_text_field()`
- textarea словаря: отдельная строгая нормализация
- список slug: построчная очистка + `sanitize_title()`

## 5. Вывод

- текст: `esc_html()`
- атрибуты: `esc_attr()`
- URL: `esc_url()`
- textarea: `esc_textarea()`

## 6. Секреты

- application password не писать в лог;
- application password не показывать в открытом виде после сохранения;
- в UI можно отображать только masked placeholder;
- не включать секреты в `context_json`.

## 7. Публичные поверхности

В MVP запрещено создавать:
- публичные REST endpoints для запуска синхронизации;
- небезопасные AJAX actions без прав;
- front-end hooks, через которые можно инициировать sync.

## 8. Cron

Cron должен вызывать внутренний hook без участия внешнего пользователя.

Если делается ручной endpoint для системного cron, его лучше не добавлять в MVP.
Достаточно:
- запланированного WP-Cron hook;
- рекомендаций настроить системный cron на стандартный `wp-cron.php` или WP-CLI cron event run.

## 9. Защита от двойного запуска

Нужен lock-механизм, иначе возможны:
- дублирование операций;
- гонки обновления;
- повреждение логов.

## 10. Логи

В логах разрешено хранить:
- время запуска;
- тип запуска;
- счётчики;
- краткий текст ошибки.

В логах нельзя хранить:
- application password;
- raw authorization header;
- полные дампы remote ответов с чувствительными данными.
